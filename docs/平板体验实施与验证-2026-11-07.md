# 平板体验实施与验证

本轮以 GitHub 主分支 v1.18.12、提交 `c902b5e` 为基线，保留现有原生 HTML/CSS/JavaScript 实现。

资料检索包含抖音公开页面及文稿。原视频未成功播放，因此没有把文稿当成已看过的视觉演示。可核实的适配依据来自钱迹官方平板更新说明、开发者发布页和 Apple 布局、导航及触控指南，具体链接见[参考记录](抖音与平板交互参考-2026-11-07.md)。

## 实现选择

| 可用窗口 | 导航与页面 |
| --- | --- |
| 宽度不足 760px 或高度不足 560px | 底部导航和单列内容，适用于窄分屏及短窗口 |
| 760–1179px 且高度足够 | 88px 紧凑侧栏，首页概览与快捷入口并排，流水单列 |
| 1180–1279px 且高度足够 | 紧凑侧栏，概览与流水分栏 |
| 1280px 起且高度足够 | 220px 完整侧栏，概览与流水分栏 |

金额键盘在宽度至少 1000px、高度至少 560px 时可与表单并排；窗口缩小时回到单列。采用窗口尺寸而非设备型号判断，因此同一平板可连续切换横屏、竖屏和分屏。

触屏窗口宽度至少 500px 时，核心入口实际点击面积采用至少 44 CSS px 的设计值。此数值是本项目的网页触控选择，不将原生平台的 pt、dp 与 CSS px 当作相同单位。

概览刷新可能晚于流水返回。原逻辑会先把预算卡搬入概览，随后概览替换 DOM 将预算卡覆盖。本轮在概览刷新完成后再排布，并在新预算卡出现时移除旧副本。新增延迟返回回归先复现预算卡丢失，再验证修复。

## 浏览器实测

使用隔离的本机 Chrome、触控模拟及虚构游客账目，外部数据请求全部拦截。

| 首页窗口 | 原流水宽度 | 改后流水宽度 | 改后导航宽度 |
| --- | --- | --- | --- |
| 1024×768 | 696px | 860px | 88px |
| 1080×810 | 448px | 860px | 88px |
| 1194×834 | 562px | 754px | 88px |
| 1280×834 | 本轮未保存该尺寸的旧截图 | 728px | 220px |

- 17 组窗口覆盖 390、500、759/760、768、820、834、1024、1080、1179/1180、1194、1279/1280、1366px 宽度，以及 559/560px 高度边界，首页与统计均无横向溢出。
- 3 轮搜索、清除、旋转、切页后，相关页面预算卡保持一份；资产与我的页没有残留预算卡。
- 编辑金额 123.45 并填写备注，经过 1194×834、834×1194、500×834 间共 6 次窗口调整，保留草稿、键盘状态及可见的保存入口。保存后恰好新增一笔，刷新后金额和备注保持。
- 39 项浏览器场景通过，页面异常为 0；自动化测试 165 项通过。

真实 iPad/Android 平板上的软键盘、系统分屏手势、读屏器与触觉尚未实测。抖音原视频未完整播放，具体交互依据与资料边界已单独记录。
