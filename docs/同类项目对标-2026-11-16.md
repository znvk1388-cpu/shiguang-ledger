## 一、重点候选项目（详查）

### 1. Wallos —— 订阅/固定支出管理中心（最值得借鉴）
- 地址：https://github.com/ellite/wallos ；官网 https://wallosapp.com
- 活跃度：README 含近期新增的 OIDC 环境变量声明式配置、SSRF allowlist、AI 推荐等特性，处于持续维护状态；第三方评测（lemsubs.com，2026-05-02）称其为「2026 年 self-hosted 订阅追踪的事实标准，仓库活跃」。星标数未核实（GitHub API 被本机网络 403）。
- 核心差异功能（README「Features」一节，已抓取全文）：
  - 订阅管理：续费日跟踪、到期不漏缴；**取消提醒**（cron 里专门有 `sendcancellationnotifications.php`，即"免费试用快到期"提醒）；
  - **年化成本视角**：cron `storetotalyearlycost.php` 每周归档"总年度成本"，把月订阅折算成年账单口径；
  - Logo 搜索：自动为订阅找服务商 logo；
  - 多通知渠道（email/telegram/webhook 等）+ 多币种折算（Fixer API）；
  - AI 推荐（ChatGPT/Gemini/Ollama）按周/月生成省钱建议。
- 对拾光记账可借鉴点：在现有「周期记账」之上加一个**订阅/固定支出专视图**——纯前端即可实现：①按"月均/年化"两种口径汇总周期账；②列表按"距下次扣款天数"排序并高亮 7 天内到期项；③加"试用/可取消"标记字段（可放备注或本地设置，不动账目结构）。完全原生 JS 可做。
- 来源：https://github.com/ellite/wallos （Features、Usage/cronjobs 段）；https://lemsubs.com/best/open-source-subscription-tracker

### 2. Spliit —— AA 共享结算 + 票据扫描建账
- 地址：https://github.com/spliit-app/spliit ；官方实例 https://spliit.app
- 活跃度：README 含 Playwright E2E、运行时环境变量、`gpt-5-nano` 默认模型等描述，属 2025-2026 持续迭代项目；MIT 协议。
- 核心差异功能（README「Features」）：
  - 群组内**每人余额**（balances）+ **「报销/reimbursement」类账目**（把"我还你钱"也作为一种 expense 类型，不污染消费统计）；
  - 不等分分摊（按份/百分比/精确金额）；
  - **拍收据自动建账**（vision 模型抽取金额/日期/分类，schema 不匹配时明确报"识别失败"而不是瞎猜）；从标题自动推断分类；
  - 群组删除走 30 天宽限期可恢复；费用可附图片凭证；群内搜索。
- 对拾光记账可借鉴点：共享账本（已有加密快照同步）里补上**"每人应付/应收余额 + 结算建议"**：纯 JS 按 participant 聚合即可；"结算"作为一种账目类型，用现有类别/备注承载，不改数据结构。识别失败时显式提示而非填猜测值——这个交互也值得抄进 AI 记账。
- 来源：https://github.com/spliit-app/spliit （Features、Opt-in features 段）

### 3. SplitPro —— AA 结算的工程细节
- 地址：https://github.com/oss-apps/split-pro ；https://splitpro.app（旧社区实例已停更，项目本身活跃）
- 活跃度：README 含 v1→v2 迁移文档、Docker/GHCR 镜像、Proxmox 脚本等，2025-2026 活跃维护。
- 核心差异功能（README「Core features」）：
  - 6 种分摊方式：equal / percentage / share / exact / **adjustments（调整项）/ settlements（结算）**；
  - **负数账目表示退款与更正**（不删原账，允许 -100 元冲抵）；
  - **活动流（activity feed）记录每笔编辑与删除**——谁改了什么留痕；
  - 每人/每组余额明细；PWA + 推送通知；收据本地存储附件；
  - FAQ：金额全部按整数（BigInt）存储避免浮点误差；**除不尽的尾差按确定性规则分摊到个人**。
- 对拾光记账可借鉴点：①共享账本结算的**尾差确定性分摊规则**（按金额+日期排序依次 +1 分，纯 JS 十几行）；②账目编辑/删除**活动流水**（可存本地 IndexedDB 独立 store，不动账目结构）；③用负账目冲销退款而非删除重记。
- 来源：https://github.com/oss-apps/split-pro （Core features、Usage overview、FAQ 段）

### 4. Ocular —— 跨年预算与财年机制
- 地址：https://github.com/simonwep/ocular ；演示 https://simonwep.github.io/ocular
- 活跃度：作者 simonwep（知名前端工具作者）；README 列有 milestone/releases，2024-12 Cloudron 论坛已收录，属活跃 PWA 项目。
- 核心差异功能（README「Features」）：
  - **跨多年追踪预算** + All-time 总览分析；
  - **自定义财年（financial year 可从任意月份开始）**；
  - **预算结转到下一年（carry over）**；
  - 仪表盘含 **Sankey 桑基图**资金流向；键盘导航；公共场合隐私模式；行内表达式求值。
- 对拾光记账可借鉴点：①**财年起始月可配置**（如 4 月制财年），影响报表中心与预算口径——纯日期运算；②**跨年 All-time 预算总览**（现有年度视图外的"自开账以来"累计口径）。注意：预算结转拾光已有，不必重做；Sankey 类资金流向拾光已有。
- 来源：https://github.com/simonwep/ocular （Features 段）；https://simonwep.github.io/ocular

### 5. Ghostfolio —— 净资产/FIRE 视角（弱相关，简查）
- 地址：https://github.com/ghostfolio/ghostfolio ；官网 https://ghostfol.io
- 活跃度：**2026-04-23 发布 Ghostfolio 3.0**（官方博客：新 UI、扩展分析、多语言、技术栈升级），活跃。
- 核心差异：多账户净资产聚合（现金/股票/ETF/加密）、ROAI 等绩效口径、匿名使用。
- 对拾光记账可借鉴点：有限——拾光已有资产净值趋势；唯一可取是其"把所有账户折算到单一主币种的净资产快照 + 时间序列对比"的展示口径。
- 来源：https://ghostfol.io/en/blog/2026/04/ghostfolio-3 ；https://github.com/ghostfolio/ghostfolio

### 6. MoneyMatter / Finlynq —— AI 助手直连账本（MCP 服务器）
- 地址：https://github.com/letehaha/moneymatter ；官网 https://moneymatter.app ；Finlynq: https://finlynq.com
- 活跃度：SkillsLLM 收录页日期 2026-10-10，属 2026 年新兴项目。
- 核心差异：内置 **MCP 服务器**，让 Claude/ChatGPT 直接查询真实消费数据并代为记账/拆分/分类；银行同步、投资、多币种。
- 对拾光记账可借鉴点：拾光已有"AI 问账"，方向一致；可借鉴的是其**让 AI 能"写"而不仅"读"**——AI 记账结果直接进待确认队列的闭环（拾光的待确认队列正好是现成载体）。
- 来源：https://moneymatter.app/features/mcp-ai-assistants ；https://github.com/letehaha/moneymatter

## 二、机制类专题（跨项目）

### A. 无支出日 / 不消费挑战（No-Spend Day）
- 生态：App Store 2026 年集中出现一批此类应用——「无消费挑战-省钱打卡」（2026-11-08 更新）、NoBuy: No Spend Challenge Game、SpendZero、Kept（"破戒不清零连续天数，坚持的每一天都算"）；方法论文章：https://sparkful.app/articles/the-no-spend-day-method/923356
- 机制要点：①统计"无支出日"数量与最长连续天数；②宽容规则（破戒不清零）提高留存；③游戏化（像素小镇）。
- 拾光可落地：纯统计视图——按日聚合账目找出零支出日，首页展示"本月无支出 N 天 / 连续 M 天"；配合现有财务健康度。零新依赖。

### B. 快速记账入口（URL scheme / Web Share Target / 快捷指令）
- 证据：GitHub `splitwise-alternative` topic 描述「add expenses by voice (Siri/AI)」（https://github.com/topics/splitwise-alternative）；SplitPro 以 PWA 为推荐使用方式并支持推送。
- 拾光可落地（PWA 原生能力，零依赖）：
  1. **URL 参数预填**：`index.html#add?amount=25&cat=餐饮&note=...`，桌面/手机快捷方式一键进入预填表单；
  2. **Web App manifest `shortcuts`**：长按图标直接"记一笔/扫码/AI 记账"；
  3. **Web Share Target**：注册为分享目标，微信/支付宝里点"分享"把账单文本或截图直接送进 AI 记账/待确认队列——与现有 CSV 导入互补，覆盖"单笔"场景。

### C. 弹性预算周期（Toshl）
- 证据：Toshl 是少数支持**任意预算周期（如每两周）+ 未用额度滚动（rollover）**的应用（App Store 页面与 Bilance 对比文，https://www.bilanceapp.com/blog/bilance-vs-toshl ，2026-08-21：「Budgets can use custom periods, filter by category/tag/account, and roll unused amounts forward」）；预算可只对特定分类/标签生效（https://toshl.com/blog/how-to-set-up-your-budgets-and-control-your-spending-web-app ）。
- 拾光可落地：现有月预算 + 结转之上，增加"周期起点日"与"每 N 天/每两周"两种周期口径——纯日期运算；拾光已有预算结转，rollover 不必重做。

### D. 端侧收据 OCR（参考）
- emanuelegala…/Receipt：Android 端侧 OCR（RapidOCR / PP-OCRv4 模型）拍照识别收据， entirely on-device（https://github.com/emanuelegaliano/Receipt ，搜索快照显示 4 天前有提交）。拾光已有 AI 票据识别（云端），端侧方案在无网/隐私场景是补充方向，但引入模型与"无新依赖"约束冲突，仅记录不推荐。

### E. 已有功能重叠项（不推荐）
- 消费热力图：Sunflow 的 GitHub 式热力图（https://github.com/ASLAM-byte/Sunflow---Budget-Tracking ）——拾光统计页**已有年度热力图**。
- 报销流程：拾光本机设置**已有报销进度/对账标记**；Spliit 的"结算型账目"是其增量（见上文条目 2）。
- 日历式记账（DailyBean calendar-first）：拾光已有日历视图。

## 三、简查候选（低优先级 / 低置信）

- **Pachas**（https://github.com/IvanBeke/Pachas ）：self-hosted Splitwise 替代，含周期支出、结算建议、Splitwise 导入。与 Spliit/SplitPro 机制重叠，无需单独借鉴。
- **tally**（https://github.com/moneytosms/tally ）：朋友群分摊 + UPI 结算，"不碰钱"定位；搜索快照显示 4 天前有提交，活跃。UPI 是印度场景，机制上无增量。
- **debt-master**（https://github.com/hogan-yan/debt-master ）：职场"代付午餐钱"场景的债务追踪，场景化产品，机制同 AA 结算。
- **DoTheSplit**（https://github.com/julian-alarcon/DoTheSplit ）：含收据扫描与图片存储的群组分摊，同上。
- **Bluecoins**：闭源 Android。功能清单页 https://www.bluecoinsapp.com/featurelist 返回 404（404 页面已核实），仅 App Store 页可证其为"报表+预算+金钱管理"工具（https://apps.apple.com/us/app/bluecoins-finance-and-budget/id1590297575 ）；Slashdot 简介提到 bills/订阅与净资产（https://slashdot.org/software/p/Bluecoins/alternatives ）。**低置信**，且其 bills/订阅机制可由 Wallos 条目覆盖，不单独推荐。
- **Moze**（https://moze.app ；少数文详解 https://sspai.com/post/54597 ）：闭源，亮点是**信用卡/花呗还款场景建模**（把"还款"与"消费"拆成两类动作对账）。拾光已有信用卡管家，机制重叠度未知（README 未展开），列为可选对照。
- **MoneyWiz / Toshl 主应用**：闭源；Toshl 机制已抽到专题 C，MoneyWiz 未深查（其核心卖点银行直连在国内场景不可用，止损）。
- **SubTrackr / Subs 等订阅追踪器**：见对比文 https://subvault.io/blog/open-source-subscription-tracker （2026-11 前后），机制均可被 Wallos 条目覆盖。
- **Moneynote / Simple Accounting**：国内开源记账（smzdm 横评 https://post.smzdm.com/p/arzp200x 、腾讯云 https://cloud.tencent.com/developer/article/2526903 ，2025-05-31），功能为常规记账+Docker 部署，未见差异化机制，止损不深挖。

## 五、推荐的前 5 个可落地借鉴点（摘要）

1. **订阅/固定支出专视图**（年化成本 + 7 天内到期高亮 + 可取消标记）——出自 Wallos。
2. **共享账本 AA 余额 + 结算建议 + 尾差确定性分摊**——出自 Spliit / SplitPro。
3. **无支出日计数与连续天数鼓励（破戒不清零）**——出自 NoBuy/Kept 类应用与 no-spend 方法论。
4. **URL 参数预填 + manifest shortcuts + Web Share Target 三件套快速记账**——出自 SplitPro（PWA 优先）与 splitwise-alternative 生态的语音/快捷建账思路。
5. **财年起始月可配置 + 跨年 All-time 预算总览**——出自 Ocular。

以上全部可在纯原生 JS PWA 内实现：不新增依赖、不改账目数据结构（新增信息走备注/本地设置/独立 IndexedDB store），多数是对既有周期账、共享账本、预算、AI 记账模块的视图与口径增强。
