## 结论：本轮采纳的手感细节（v1.19.6 落地）

1. **触感反馈（navigator.vibrate）**——源自 Android 生态与 ezBookkeeping（Framework 7 App 的 HapticFeedback）的普遍实践。
   - 三档短模式：轻点 9ms（键盘、切页、下滑关闭成功）、成功 20ms（记账落库）、警告 [15, 70, 24]（校验失败、移入回收站）。
   - 尊重 MDN 约束：仅在有用户激活的交互里调用；iOS Safari 等不支持环境静默跳过；`ledger10_haptics` 本机开关（我的 → 外观与提醒 → 触感反馈），默认开，并纳入 overlay 备份键清单。
2. **底部弹层下滑关闭 + 顶部拖拽把手**——Framework 7 sheet 的 swipe-to-close 是移动 Web 的成标准；本项目弹层此前只能点「关闭」或遮罩。
   - 仅移动端底部弹层布局（<640px 或粗指针）生效；面板滚到顶、起点不在按钮 / 输入框 / 键盘上才接管手势；
   - 位移超过 `max(120px, 面板高度 30%)` 或末段速度 >0.9px/ms 才关闭；短拖弹回；带未保存草稿仍走既有确认；
   - CSS 粘性把手横条（桌面居中对话框不显示）；接管期间阻断触屏滚动跟随；减少动态偏好下手势仍可用（手势不是装饰动效），回弹走既有 CSS 过渡。
3. **数字键盘与分类宫格按压缩放**——两处是记账 App 触摸频率最高的表面，此前只有变色（对照本项目 .btn/.chip 已有缩放基线补齐）：按键 scale .955、宫格 scale .94，70ms 按下 / 180ms 复位。
4. **底部导航选中弹跳（tabPop）**——切 tab 成功后图标 0.9 → 1.14 → 1 的 260ms 弹跳；沿用 animateFeedback 的按元素取消与减少动态机制。
5. **保存后首页大数字滚动（countUp）**——记账落库回到明细页时，结余 / 还能花数字从旧值滚到新值（320ms 三次缓出），只答本次保存、普通刷新不播；统计口径（预算余量 / 结余）切换时不跨口径滚动。
6. **保存成功 / 失败 / 删除的触感反馈**接在 v1.18.16 的保存状态机之后：干净成功 → success 档；校验失败 → warn 档；部分失败（报销状态没写上）不给成功触感，与图标勾选同口径。

## 明确不采纳（记录原因）

- **Material ripple 波纹**：与既有「轻缩放」语言冲突，且全站铺开改动面大；保留缩放路线。
- **下拉刷新**：本地 IndexedDB 数据无「新内容」可拉，做了只会成为误触来源。
- **骨架屏**：本地数据毫秒级返回，骨架屏反而闪屏；弹层内的「正在计算…」已有。
- **列表行按压缩放**：通宽行的缩放在 iOS 原生列表里也只做背景染色（本项目已有），缩放会让通宽行出现两侧露底。
- **iOS 触感**：Web 无法调用（iOS Safari 不实现 Vibration API），说明文案里已如实告知，不假装支持。

## 待证项

1. 真机震动强度：9ms/20ms 在不同马达上的主观强弱需要真机验收（jsdom 只能验证调用与模式）。
2. 弹层下滑在 Android WebView（微信小程序 web-view 环境）的指针事件覆盖面，待真机回归。
3. Framework 7 的 swipe-step（半开状态）本轮未做：拾光的弹层多为表单，半开状态价值低。
